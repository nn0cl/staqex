## Implementation Design

1. Move the exact pure algorithms for coordinate enumeration, function-local
   cleanup, eligible-main filtering, statement live-variable collection,
   caller cleanup, and the two AST walkers into `liveness.py`.
2. Depend only on the existing AST types and `Joint`; do not import or
   instantiate Evaluator or Observation services.
3. Preserve each current Evaluator private hook/signature as a thin delegate
   so `EvaluatorContext`, execution, observation, pipes, and evolution
   consumers remain source-compatible.
4. Keep `_expr_has_inspect` and `_expr_free_vars` dynamically installed as
   compatibility hooks whose runtime function identity is the successor's.
5. Have `frames.py` use the successor directly and delete its duplicate bodies.
6. Keep Evaluator as the only mutable runtime-state owner; do not add shared
   caches, maps, or copied state.

## Context and Process Lessons

- Included: ADR 0228, accepted spec, reviewed tests, evaluator/frames/
  observation bodies, actual compatibility installer, private consumer and
  test inventories, verification policy.
- Omitted: unrelated evaluator modules, external providers/QPU, broad
  optimization or semantic expansion.
- Assumptions: no control-flow or behavior change is required; if it is,
  implementation stops for review.
- Applied: acceptance-inventory-reconciliation (all ADR clauses map to tests),
  compatibility-hook-identity-contract (runtime identity),
  private-consumer-inventory/decomposition-callback-boundary (preserve all
  existing callback surfaces), evaluator-state-ownership (no second state
  owner), status-drift (synchronize all current records).
- Routing: host implementation and same-context review per runtime-routing;
  no model override.
